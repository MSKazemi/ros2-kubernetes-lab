Phase 3 · days 31–60

Package and document, with evidence for every claim

By this phase the lab should have a proven cross-worker path to describe. Now the job is to explain it truthfully: a clear README, benchmarks anyone can rerun, tutorials that stay correct as versions change, and a first release that comes only after validation.

Proposal · planning targets, not promisesIssues #17, #18, #19, #20Source: docs/ROADMAP-2026.md

Where this phase starts

The roadmap's audit (10 to 11 October 2026) found gaps that this phase exists to close. These are starting points, not results.

Gap

No proof-of-function demo yet

The root README has no central demo animation and no validated modern install profile. Its main example starts a CPU stress test (stress-ng), not a ROS 2 talker and listener.

Gap

No tagged release

At the audit the repository had no GitHub release. The plan holds the first one back until a clean install has been validated.

Historical

Old measurements exist

The DataAnalysis/ folder holds sample monitoring files from a single recording on 2024-04-20 on the historical Vagrant lab cluster. They stay labelled historical and are never quoted as modern results.

Every claim carries its evidence

This phase follows one rule: a statement the lab publishes must point to something that backs it. Step through the four artifacts and watch each claim get its evidence. The last row shows a claim with nothing behind it, which stays out.

Three rules this phase keeps

Historical stays historical

New benchmarks come from controlled new runs. Old sample files are kept and clearly labelled as old. They never appear as results for the modern profile.

Release only after validation

The first tagged release follows the validation of a clean install. If that takes longer, the release waits. The plan holds a milestone rather than skip a gate.

Legacy steps are separated

The old Foxy steps stay available but are marked as historical, and the phase adds a migration note for people still on them.
