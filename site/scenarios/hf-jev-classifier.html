01 / Research challenge

Why this problem is interesting

A synthetic incident corpus contains DDS discovery, QoS mismatch, connectivity, resource pressure, healthy and unknown cases. Build proper train/dev/test partitions; do not assume an arbitrary general-purpose pretrained text model already knows these labels.

Falsifiable question

Where does Jev add value over a reproducible local HF classifier, if anywhere?

Working hypothesis

Jev Choice may change diagnosis quality or coverage, but hosted latency, cost, class calibration and outage behavior may make a local classifier or deterministic rules preferable.

Null hypothesis

Under the same held-out incidents, optional Jev achieves no better selective risk/coverage or utility than a licensed pinned Hugging Face classifier and rules.

Hugging Face capabilities involved

  • HF Hub Model & Model Card
  • HF Transformers / pinned tokenizer
  • Jev Choice via optional hosted API
  • Local deterministic rules
  • Dataset splits + reproducible run manifest

Who can contribute?

Python NLP evaluation · AI benchmarking · Model calibration

Required prerequisites: Existing #74/#75 fault PoC and evaluation, #84 synthetic casebook, #58 HF revision pinning. A model card or benchmark cannot be created honestly without an actual model/run.

03 / Reproducible experiment design

Experimental variables, controls and metrics

A useful research scenario is more than a diagram. These are the testable claims and artifacts future contributors should implement or report.

Design elementHow it should be investigated
Evaluation armsMajority/unknown control; rule baseline; CPU-friendly HF text classifier fine-tuned/mapped to classes; optional Jev Choice; optional constrained LLM.
Held-out splitGroup by incident family and logger variant; unseen-root-cause/OOD subset and injected-log negative cases.
VariablesClass prevalence, missingness, prompt/choice order, model/tokenizer revision, hosted failures and network RTT.
EndpointsMacro-F1, critical class recall, selective risk vs coverage, multiclass Brier/ECE where calibrated probabilities exist.
OperationsEnd-to-end p50/p95/p99 request time, memory/CPU, outage/429 rates, actual model-call costs; include rejected attempts.
Audit trailHF model commit + dataset license, criteria/response model hash, seed, run manifest, raw predictions, failures, uncertainty.

Proposed experimental steps

  1. Publish the synthetic taxonomy and incident-family split before selecting model outputs.
  2. Implement rule and majority baselines, explicit unknown/abstention and zero-network unit tests.
  3. Identify an open HF model license and pinned tokenizer; fine-tune or map labels on the permitted training split only.
  4. With explicit budget and a valid hosted account, optionally compare pinned Jev Choice using the same evidence.
  5. Publish raw test predictions, failures, cost and uncertainty only after actual executed runs.

Expected contributions

  • Synthetic ROS2 incident dataset + classification rubric
  • Pinned HF classifier/model card (only if actually trained/evaluated)
  • Jev structured adapter (optional, hosted) + deterministic policy tests
  • Fair benchmark code, calibration and abstention plots from verified runs

Publication gate: no result without a source revision, licensed data, raw positive and negative runs, exact method, uncertainty, and human review.

Safety and deployment limitations

Do not ship private video, motor command streams, sensitive lab addresses, access tokens or unlicensed model weights. Hard eligibility, quotas, version checks, deadlines and actions remain in deterministic code. Jev is advisory only where included.

Hugging Face integration and external model services may require credentials, licensing review, a subscription or usage charges. Public demos must not claim any official partnership or endorsement.
