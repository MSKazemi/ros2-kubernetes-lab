01 / Research challenge

Why this problem is interesting

A fictional robot records task, joints, action vectors and camera frame metadata. The first exercise uses JSON metadata only. Real LeRobotDataset v3 requires actual Parquet/video representation and a successful loader round trip on a pinned version; it is NOT created by the website.

Falsifiable question

Which metadata errors are detectable offline before a dataset reaches the Hub?

Working hypothesis

Explicit schema, units, timestamp and redistribution checks reject more invalid episode definitions than a permissive ingest process, without blocking valid licensed synthetic examples.

Null hypothesis

Structured prepublication checks provide no meaningful increase in detecting invalid episode definitions over naive parsing.

Hugging Face capabilities involved

  • ROS 2 observation metadata
  • LeRobotDataset v3
  • Hugging Face Hub Datasets
  • Dataset card & Dataset Viewer
  • Immutable HF revisions

03 / Reproducible experiment design

Experimental variables, controls and metrics

A useful research scenario is more than a diagram. These are the testable claims and artifacts future contributors should implement or report.

Design elementHow it should be investigated
CorpusAt least 12 synthetic positive/negative metadata cases; separate deliberately incomplete examples and record expected rejection codes.
Independent variablesMissing camera layout, mixed degrees/radians, sample-clock drift, invalid action dimension, unclear task caption, unknown license.
BaselineNaive metadata JSON parse versus strict schema/semantic/privacy validation. JSON parse is not LeRobot-format verification.
ChecksLeRobot v3 official loader round-trip on pinned release; verify episode count, modality keys, frame/timestamp alignment and dataset card.
MeasurementsInvalid-case detection, valid acceptance, rejection reason agreement, data conversion integrity and future upload/retrieval failures.
EvidenceDataset commit hash, converter/source SHA, tool/version, license, synthetic-data declaration, scripts and loader/test output.

Proposed experimental steps

  1. Define source episode ontology with units and time base; never treat filenames as proof of content.
  2. Create licensed, fabricated metadata fixtures; demonstrate deterministic reject/accept/unknown behavior.
  3. Choose a specific LeRobot release and map its v3 observation/action/episode schema.
  4. If building a converter, verify finalize and reload with official LeRobotDataset API; log all errors.
  5. Only after permission and human review may a real Hub Dataset be published and linked in a card.

Expected contributions

  • Synthetic lesson + casebook, rule baseline and failing fixtures
  • Validated converter design / optional genuine LeRobot v3 reload test
  • Dataset card with provenance, splits, license, consent and limitations
  • Immutable HF dataset revision and actual Hub URL only after upload

Publication gate: no result without a source revision, licensed data, raw positive and negative runs, exact method, uncertainty, and human review.

Safety and deployment limitations

Do not ship private video, motor command streams, sensitive lab addresses, access tokens or unlicensed model weights. Hard eligibility, quotas, version checks, deadlines and actions remain in deterministic code. Jev is advisory only where included.

Hugging Face integration and external model services may require credentials, licensing review, a subscription or usage charges. Public demos must not claim any official partnership or endorsement.
