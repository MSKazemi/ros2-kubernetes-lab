01 / Research challenge

Why this problem is interesting

A hypothetical pick-and-place task uses one declared LIBERO suite. An upstream policy must be confirmed compatible with that suite's action shape, camera channels, normalization and task description. A base checkpoint is not automatically a working robot policy, and no LIBERO run is performed in the browser.

Falsifiable question

What evidence establishes simulator task success beyond loading or warmup?

Working hypothesis

Task outcomes depend strongly on compatible observation/action semantics, data and simulator settings; held-out episode results may not match plausible single-run behavior.

Null hypothesis

Changing one predeclared compatibility/representation factor yields no measurable task-outcome difference under matched, valid simulator trials.

  • LeRobot training & lerobot-eval

03 / Reproducible experiment design

Experimental variables, controls and metrics

A useful research scenario is more than a diagram. These are the testable claims and artifacts future contributors should implement or report.

Design elementHow it should be investigated
EnvironmentLeRobot LIBERO suite under a fixed released LeRobot version; choose a known-compatible checkpoint and document GPU/MuJoCo prerequisites.
WorkloadPredefined task subset, initial states/episode seeds, matched reset strategy and fixed number of episodes.
VariablesCamera-name mappings, observation tensors, action relative/absolute mode, normalization and dataset/model revisions.
BaselinesVerified upstream compatible checkpoint, task-random or rule baseline where meaningful; vary one factor at a time.
EndpointsPer-task and overall completion fraction, rollout failure types, latency, VRAM/CPU, reproducibility across seeds.
GuardrailsNo physical robot; reject incompatible schema and unlicensed weights; don't equate successful warmup with task success.

Proposed experimental steps

  1. Choose a supported simulator and a license-compliant, pretrained or fine-tuned policy with verified compatible inputs.
  2. Pin model and dataset commits, processor configuration, container/LeRobot version and task reset semantics.
  3. Run a minimal smoke test with explicit expected observables and stop conditions only on authorized equipment.
  4. Execute matched seed/repetition protocol, preserve successful and failed episodes, and compute uncertainty.
  5. Create a model card and public plots only if the artifact and real evaluated results exist and can be inspected.

Expected contributions

  • Compatibility matrix for model/dataset/environment/action modes
  • Documented LeRobot CLI recipe for a pinned version (conditional on actual compatibility)
  • Raw simulator episode traces and run manifest (future)
  • License-aware model card and verified per-task analysis

Publication gate: no result without a source revision, licensed data, raw positive and negative runs, exact method, uncertainty, and human review.

Safety and deployment limitations

Do not ship private video, motor command streams, sensitive lab addresses, access tokens or unlicensed model weights. Hard eligibility, quotas, version checks, deadlines and actions remain in deterministic code. Jev is advisory only where included.

Hugging Face integration and external model services may require credentials, licensing review, a subscription or usage charges. Public demos must not claim any official partnership or endorsement.
