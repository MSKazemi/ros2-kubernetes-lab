02 / Evidence contract

What a result submission must contain.

01 / INPUTS

Frozen experiment

Task and null hypothesis, exact dataset/split and license, source and container commits, model/revision and question criteria hash, hardware/clock and network profile.

02 / RUNS

Raw and failed outcomes

Run IDs, seeds, repeats, all valid/invalid/unknown predictions, provider outages, latency with units, actual measurement source and cost assumptions.

03 / REPRODUCTION

Independent review

Raw shareable files, SHA-256 hashes, scripts and exact replay commands, calculated uncertainty and limitations, human-reviewed evidence URL.

Status rules

  • Planned: question and methodology exist; measured values must remain null.
  • Collecting: trial evidence is under review; measured values remain undisplayed.
  • Verified: public evidence, immutable run manifest hash and numerical metric exist and were independently reviewed.

Research safeguards

Use synthetic or licensed data; never commit secret tokens, private ROS telemetry, real robot addresses or unapproved human recordings. Independent deterministic safety controls and simulator-only boundaries are mandatory. Neither TypeSafe nor this website certifies a robot controller.

03 / Contribute results

Publishing a negative finding is valuable too.

Propose a reproducible experiment

Before submitting claims, read the scenario, preregister metrics and create a small issue/PR that includes scripts, synthetic or licensed raw data, failures, and an evidence manifest. See the dedicated results issue and Claude Code/Codex instructions.
