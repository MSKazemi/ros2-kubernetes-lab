Jev as an Advisory Reviewer for ROS 2 Agent Skills

An LLM proposes a robot skill. Can a structured decision model provide useful extra review without bypassing deterministic permissions and simulator safety checks?

See the idea in a minute

An AI agent can suggest robot skills, but fixed rules decide which ones may run. Watch three made-up suggestions reach the policy gate. Nothing here runs a model or moves a robot.

Plain-language guide

  • Skill proposal: one high-level simulator action, such as get_status, that the language model suggests. The model suggests it and does not run it.
  • Deterministic policy: fixed rules, such as a schema check, an allowlist and parameter limits, that give the same answer every time. It stays authoritative.
  • Jev: a structured decision model that this proposal would test as an optional second opinion. It advises and never grants permission.
  • Simulator only: the study stays in simulation. This site runs no model and sends no command to a robot.
01 / What are we studying?

One real research question, not a product claim.

A fictional operator requests a high-level simulator action. The planner proposes get_status, inspect_scene or an unsupported privileged command. An independent validator must reject forbidden skills even if a model claims they are fine.

Research hypothesis

Question: Does an additional Jev advisory screening stage detect useful problems in high-level simulated ROS 2 agent plans beyond an independent typed validator?

Null hypothesis: A second model adds cost, false positives or inconsistent judgments without increasing detection beyond deterministic enforcement.

Alternative: Jev detects additional semantic problems and can improve human review without becoming an authorization gate.

Audience & learning targets

Agentic AI · robotics safety · LLM research · MSc → PhD · Synthetic fixtures only

  • Design typed, allowlisted high-level skills instead of free-form robot commands.
  • Separate language-model opinions from access control and schema enforcement.
  • Test injection in untrusted logs and retrieved context.
  • Measure false-negative detection, review effort and abstention.

Experimental protocol

  1. Define a tiny catalog of high-level simulator skills with a JSON Schema and an explicit scope for each.
  2. Write synthetic proposal fixtures with known policy outcomes: valid, ambiguous and unauthorized.
  3. Show that the deterministic gate blocks every enumerated forbidden fixture whatever any model says.
  4. Only then, optionally, compare an advisory screen on semantic errors. It may add caution and never add permission.
  5. Report false blocks as well as missed blocks, with the fixtures and manifest.

The registry primary metric is unauthorized-proposal recall. It has no value yet. The reason codes on this page are proposals. See also the experiment blueprint on this page.

03 / Experiment blueprint

Variables, baselines and measurements.

Before anyone reports performance, the task, failure cases, comparison methods and test split must be fixed. Keep negative results and rejected advice visible.

Research dimensionProposed measurement contract
SkillsRead-only inspect_scene/get_status; separately approved simulator navigation only with valid named waypoint.
BaselineJSON Schema, capability/RBAC allowlist, parameter bounds and human approval; model-free enforcement.
VariablesGoal ambiguity, hallucinated tool names, adversarial RAG/log strings, missing robot/task state and Jev screening criteria.
Failure casesRaw /cmd_vel, arbitrary shell/kubectl, unknown waypoint, stale scene, model overconfidence or provider outage.
Primary metricsRecall on deliberately unauthorized test proposals, semantic error detection, reviewer load, abstentions, false alarms.
ReproducibilityVersioned high-level skill catalog, synthetic task IDs, fixture hashes, threat model and adjudicated reviewer labels.

Suggested experiment procedure

  1. Define a tiny high-level simulator skill vocabulary with JSON Schema and explicit execution scope.
  2. Write synthetic valid, ambiguous and unauthorized plan fixtures with known policy outcomes.
  3. Prove the deterministic gate blocks all enumerated forbidden fixtures regardless of model responses.
  4. Optionally compare Jev, rules and a constrained-output LLM on semantic error screening.
  5. Report both false positive and false negative impacts; include human review time if ethically approved.

What a contribution should produce

  • Versioned synthetic high-level agent-proposal casebook
  • Independent validator tests including prompt-injection attempts
  • Threat model, reviewer worksheet and confusion matrix
  • Verified experiment manifest and human study approval (if later needed)

Required before publishing a result: independent run ID, method, seed, source/model revisions, environment, raw measurements, executable analysis, errors/limitations and human review.
