01 / What are we studying?

One real research question, not a product claim.

A fictional ROS 2 listener has missed a publisher's messages. The provided record might point to QoS incompatibility, DDS discovery, missing connectivity, or insufficient evidence; the underlying cause is deliberately not assumed.

Research hypothesis

Question: Can a bounded Jev Choice improve held-out synthetic incident classification over a deterministic rule baseline without overconfident diagnoses?

Null hypothesis: Jev offers no meaningful increase in macro-F1 or selective coverage at a fixed error rate compared with a simple offline rule baseline.

Alternative: Jev adds diagnostic information on ambiguous cases while preserving an unknown/review option; this must be measured on held-out data.

Audience & learning targets

ROS 2 students · SREs · teaching assistants · Beginner → MSc · Laptop only for casebook

  • Distinguish ROS 2 application nodes from Kubernetes worker nodes.
  • Identify reliability and durability QoS mismatches versus DDS discovery gaps.
  • Treat ambiguous logs as evidence, not commands; practice abstention.
  • Measure a structured classifier against a deterministic baseline.

03 / Experiment blueprint

Variables, baselines and measurements.

Before anyone reports performance, the task, failure cases, comparison methods and test split must be fixed. Keep negative results and rejected advice visible.

Research dimensionProposed measurement contract
Dataset20–40 starter synthetic incidents across discovery, QoS, network, resource, healthy and unknown; family-grouped held-out test set for later research.
BaselineRule-based event triage and majority-class/always-unknown controls. Define label criteria before model evaluation.
VariablesEvent completeness, contradictions, ROS distro wording, log injection, Choice option order and Jev question wording.
Failure casesStale timestamp, missing QoS metadata, conflicting evidence, API 429/timeout, malicious text inside a simulated log.
Primary metricsMacro-F1, per-class recall and selective risk vs accepted-coverage; measured end-to-end p95 and provider availability later.
ReproducibilitySeed, synthetic fixture family, model/request revision, criteria hash, failures, abstentions and exact source commit.

Suggested experiment procedure

  1. Author a small licensed synthetic incident corpus with class rationale, ambiguity flags and family IDs.
  2. Specify the input/output schema and deterministic rules (no provider key required).
  3. Split by incident family; preserve a held-out test set and preregister evaluation targets.
  4. Optionally query pinned Jev on sanitized synthetic state with an explicit cost/network budget.
  5. Report accepted/rejected/unknown outcomes, confidence calibration and runtime/cost evidence from real runs only.

What a contribution should produce

  • Synthetic incident casebook + label guidelines
  • Versioned schema and offline baseline tests
  • Reproducibility manifest and raw predictions (only after actual runs)
  • Error analysis and confidence/abstention charts (only from observed data)

Required before publishing a result: independent run ID, method, seed, source/model revisions, environment, raw measurements, executable analysis, errors/limitations and human review.
